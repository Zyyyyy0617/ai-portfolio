# M1 会话协议草案 v0.1（阶段 A）

> 范围：客户端（Web / 桌面 / 移动）与服务端之间的一次语音/文本会话；文本与音频事件走同一条通道。
> 传输：WebSocket + JSON 信封；音频暂用 base64 文本帧（后续可换二进制分片）。协议版本 `v=1`。

## 1. 事件类型与字段

### 1.1 公共信封

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `v` | int | ✓ | 协议版本，当前 `1` |
| `session_id` | string | ✓ | 会话 ID（ULID），由服务端在 `session.ready` 下发 |
| `seq` | int | ✓ | 同一方向内单调递增，从 1 开始；排序与去重的唯一依据 |
| `ts` | int | ✓ | 毫秒时间戳；上行=发出时间，下行=服务端落库时间 |
| `type` | string | ✓ | 事件类型，见下表 |
| `payload` | object | ✓ | 类型相关负载，无内容时为 `{}` |
| `reply_to` | string | – | 应答关系，如 `tool.result.reply_to = call_id` |

### 1.2 事件类型

| 方向 | type | payload 关键字段 |
| --- | --- | --- |
| 上行 | `session.start` | `client{platform,app_version}`, `resume_from?` |
| 上行 | `text.input` | `text`, `client_msg_id` |
| 上行 | `audio.chunk` | `turn_id`, `chunk_index`, `format`, `data` |
| 上行 | `audio.end` | `turn_id` |
| 上行 | `control.interrupt` | `turn_id`, `reason`, `last_played_seq` |
| 上行 | `ping` | `{}` |
| 下行 | `session.ready` | `session_id`, `resumed`, `server{model,tts}` |
| 下行 | `asr.partial` / `asr.final` | `turn_id`, `text` |
| 下行 | `agent.thinking` | `turn_id` |
| 下行 | `tool.call` | `turn_id`, `call_id`, `name`, `args` |
| 下行 | `tool.result` | `turn_id`, `call_id`, `ok`, `result` \| `error` |
| 下行 | `tts.chunk` | `turn_id`, `chunk_index`, `format`, `data` |
| 下行 | `agent.final` | `turn_id`, `text`, `aborted?`, `usage?` |
| 下行 | `error` | `code`, `message`, `retryable` |
| 下行 | `session.reset` | `reason`, `snapshot` |
| 下行 | `pong` | `{}` |

```json
{"v":1,"session_id":"01JCF3K8...","seq":7,"ts":1763964000123,
 "type":"tool.result","reply_to":"call_01",
 "payload":{"turn_id":"t_3","ok":true,"result":"3 级共 2 个词"}}
```

## 2. 状态机

`idle → listening → thinking → tool_calling → speaking → idle`

| 当前 | 事件 | 下一状态 | 说明 |
| --- | --- | --- | --- |
| idle | `session.start` | listening | 会话建立 |
| listening | `audio.end` / `text.input` | thinking | 一轮请求提交 |
| thinking | 模型决定调用工具 | tool_calling | 可能有多次，串行 |
| tool_calling | `tool.result` | thinking | 回到模型继续推理 |
| thinking | 首段 `tts.chunk` | speaking | 边说边生成 |
| speaking | `tts` 播完 + `agent.final` | idle | 一轮结束 |
| 任意 | `control.interrupt` | listening | 打断，回退当前轮 |
| 任意 | `error`（不可恢复） | idle | 兜底 |

**打断回退细则**（必须按序）：

1. 客户端立刻停播并清空本地待播队列，**不等服务端**（体验优先）；
2. 发 `control.interrupt{turn_id, last_played_seq}`；
3. 服务端把该 `turn_id` 置 `aborted`，丢弃其后的 `tts.chunk`，取消未完成的工具调用（不可取消的标记 `late_result` 并忽略）；
4. 客户端收到 `aborted` 后，丢弃该轮 `seq` 大于确认点的所有下行事件；
5. **已确认的 `asr.final` 文本不丢**，作为下一轮上下文保留。

不允许的跳转：`listening → speaking`、`tool_calling → speaking`（必须先回 thinking）。

## 3. 权威与幂等

- **服务端唯一权威**：会话状态、`seq`、`turn_id`、最终文本以服务端为准；客户端只做乐观 UI，收到事件后必须收敛到服务端状态。
- **单一写者**：一个 session 同时只有 1 个活跃 turn；新 turn 开始前，旧 turn 必须 `completed` 或 `aborted`。
- **上行幂等**：`client_msg_id`（UUID）为幂等键，服务端保留最近 200 条 / 10 分钟；重复到达直接回上次结果，**不重复触发模型或工具副作用**。
- **下行去重**：客户端按 `(session_id, seq)` 去重；缺号 → 请求补发；乱序 → 本地按 `seq` 排序后再渲染。
- **工具幂等**：`call_id` 由服务端生成并全链路透传，执行侧按 `call_id` 保证「最多一次」副作用；写操作的工具必须自带幂等键。

## 4. 断线语义

| 场景 | 处理 |
| --- | --- |
| 重连 | 客户端发 `session.resume{session_id, last_seq}`，服务端从 `last_seq+1` 补发 |
| 补发窗口 | 5 分钟 / 1000 条（取先到者）；超出 → `session.reset{reason:"buffer_overflow"}` + 快照重建 |
| 上行未确认 | 客户端缓存未 ack 事件，重连后重发；服务端按 `client_msg_id` 去重 |
| 断线期音频 | **不补发**，直接丢弃；以 `asr.final` 为准，客户端提示「刚才没听清」 |
| 会话过期 | 服务端 TTL 30 分钟；`resume` 返回 `session.reset{reason:"expired"}`，客户端新建会话 |
| 心跳 | 15s `ping`，30s 无 `pong` 判定断线；重连退避 0.5/1/2/4s，上限 30s |
